设计语法

四条规则决定这块界面的样子

重构不改数据口径，只改表达方式。下面四条是这一版所有取舍的依据。

01 · 表面分层

通道卡浮在浅灰纸上

整块面板是 var(--surface)，每张通道卡是 var(--bg) + 一圈 var(--elev-ring)。 需要强调的模块才升一级到 var(--elev-raised)。没有阴影堆叠，也没有装饰性描边 —— 层级由明度差承担。

02 · 单色动作

蓝色只说「现在」和「可点」

var(--accent) 只出现在三处：主行动按钮、当前数据源、今日那根柱子与今天那一格。 数据条用蓝色阶（accent → accent+bg）拉开深浅，其余一律走前景灰阶。语义色只在上下文进红线区时露面。

03 · 机头三行

标题不与系统三键同处一行

第一行是窗口 chrome（整条可拖，右端给「− □ ✕」留位，左角只留一个「关于」）； 第二行才是身份与动作；第三行整行给数据源 —— 它是这一页的主导航，挤进标题行只会被压成省略号。

04 · 读不到 ≠ 0

缺账本的通道整块收起

Qoder CN 没有 token，结构卡整块不出现而不是画一排 0；OpenCode Go 只有额度，面板换成另一套卡片。 「读不到」另有载入态与告警条，绝不画成一个看起来正常的 0。

主面板原型 · 可交互

切数据源、刷新、换外观、点会话

这一版原型接的是真实口径：切到只有积分的源，token 通道会整块消失；切到额度源，面板换成另一套卡片。底轨的更新流程也可以一路点到底。

通道拆解

每个通道画什么，什么时候收起

通道顺序按「抬头 → 现在 → 历史 → 明细」排。表里写清了各账本口径下的显示差异。

通道画什么口径差异
积分 / 额度 云端积分水位、额度包明细；或三个额度窗口的水位与重置时间。 Trae CN 的积分在云端、OpenCode Go 只有百分比；其余源这一整块不出现。
今日 主读数 + 输入 / 输出 / 调用次数；右侧副读数。 有积分的源右侧报积分与比价；没有积分的换成缓存命中率；没有 token 的主读数直接报积分。
上下文 带红线区的仪表：70% / 90% 两条分界印在刻度槽上，指针进区才染色。 模型上限未知时只报已用量，不硬算百分比；只有比例的源按比例画。
结构 输入 / 缓存命中 / 输出 / 思考 的分布条。 思考 token 只有部分源单列；没有 token 的源整块收起。
14 天 每日柱状图，空档补 0 高度，今天用强调色。 没有 token 的源改画积分柱。
活跃 近 26 周点阵，五级明度，今天加一圈强调色描边。 计量单位跟随账本（token 或积分），图例同步换字。
模型 / 项目 双列排行，各取前五。 右侧数值按账本切换 token 或积分，hint 报次数 / 会话数。
会话 标题、模型、项目、相对时间、次数、水位；右侧大数与积分。 点一行即把它设为「当前会话」，仪表与托盘进度环同步 —— 原型里可以直接点。

状态

读不到、没有、出错了 —— 三种说法

界面里出现 0 只有一种可能：真的读到了 0。其余情况各有自己的画法，且都要说人话。

载入中 · 正在扫内存取密钥

正在从 Trae CN 进程读取用量库密钥
大约需要 20 秒。这段时间的数字不是 0，是还没读到 —— 所以这里一个数字都不画。

骨架只占位，不填假数；载入完成前禁用刷新，避免叠两轮采集。

空态 · 账本里没有这一层

最近 14 天没有用量
另有 12.40 积分找不到对应的会话明细（1,284 个计费回合中，只有 1,279 个能对上本地记录）。 这些多半来自已经清理掉的会话。

未归因积分单独列出，不并进会话明细，避免总额平白少一截。

取数失败

取数失败
读不到 ~/.zcode/cli/db/db.sqlite：文件被占用，或目录不存在。

失败只影响当前数据源，切到别的源照常可用；底轨与更新状态不受牵连。
